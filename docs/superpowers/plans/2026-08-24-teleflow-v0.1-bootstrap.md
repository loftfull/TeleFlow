# TeleFlow Android v0.1 Bootstrap Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a reproducible patch-layer that transforms a pinned official Telegram Android checkout into a branded TeleFlow development APK foundation.

**Architecture:** Keep TeleFlow in a small bootstrap repository. A deterministic Python patcher validates upstream anchors, injects user-owned Telegram API credentials, rebrands package/application identity, and creates a self-contained `org.telegram.teleflow` extension package. GitHub Actions checks out official Telegram and builds `afatDebug`.

**Tech Stack:** Python 3.12 stdlib, GitHub Actions, Gradle/Android SDK 35, official Telegram Android Java code.

**Spec:** `docs/superpowers/specs/2026-08-24-teleflow-v0.1-design.md`

## Global Constraints

- Product name is `TeleFlow`.
- Android application ID is `com.loftfull.teleflow`.
- TeleFlow must use user-owned `TELEGRAM_API_ID` and `TELEGRAM_API_HASH`.
- No second MTProto session may be introduced.
- Upstream modifications must fail closed if expected anchors are missing.
- Android SDK 35 and NDK 27.2.12479018 follow current upstream requirements.
- Do not copy implementation code from repositories without a clear compatible license.
